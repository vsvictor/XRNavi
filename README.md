# XRNavi

XRNavi — прототип навігаційного застосунку для **Android та iOS** зі спільним інтерфейсом на **Kotlin Multiplatform і Compose Multiplatform**, відтвореним за макетами Figma.

Проєкт поєднує планування маршрутів, покрокову та концептуальну XR-навігацію, гараж із параметрами транспорту, корпоративні завдання водія й історію поїздок. Особисті та робочі сценарії розділені, а налаштування приватності пояснюють межі доступу до даних.

## Поточний стан

Створено UI всіх **9 основних і 18 допоміжних екранів** зі схеми Figma. Екрани переведені на **Clean Architecture + MVVM**, з навігаційним стеком і спільним станом транспорту, маршруту та особистого / робочого контексту. Авторизація, картографія, GPS, камера / XR і серверні дії ще не підключені: демонстраційні дані не означають роботу реальних сервісів.

Опис екранів, Mermaid-схеми переходів і відомі обмеження: **[screens.md](./screens.md)**.

### Архітектура

Спільний Kotlin-код: `shared/src/commonMain/kotlin/com/mobilespace/xrnavi/`.

- **`domain/`** — Kotlin-моделі, контракти репозиторіїв, перевірка введення й use cases. Не імпортує Compose, ресурси, Android або iOS.
- **`data/`** — демонстраційні каталоги / адреси / завдання, репозиторії стану в пам'яті та чесні адаптери `NotConfigured`.
- **`presentation/`** — lifecycle `ViewModel`, незмінні `UiState` у `StateFlow`, методи-інтенти та одноразові ефекти. **`presentation/ui/`** містить екрани-рендерери, тему й спільні компоненти; у Compose залишено лише локальні візуальні стани, наприклад прокрутку та видимість пароля.
- **`presentation/navigation/`** — чистий Kotlin-стек `AppNavigator` із параметрами завдання, визначеними коренями вкладок і перевіркою робочого контексту. Android системне «Назад» та кнопки iOS використовують однакове повернення. ViewModel кожного запису стека має окремий `ViewModelStore`, який очищається після видалення запису.
- **`di/AppContainer.kt`** — явний composition root: тут підставляються репозиторії та створюються всі ViewModel. Екрани не створюють сервісів і не мають непомітних сервісних залежностей за замовчуванням. `App.kt` лише запускає тему, навігацію та `ScreenHost`.

`SessionRepository` і `PreferencesRepository` зберігають вибір **між екранами в межах процесу**; після перезапуску застосунку він скидається. Це не дискове чи серверне збереження. Стартові приклади містять профіль учасника Dnipro Logistics, але не надають реальної авторизації чи доступу до організації. Неучаснику вибір корпоративного контексту пропонує запрошення; зміна режиму не змінює членство.

Авторизацію не обійдено: застосунок починає з входу, а непідключений репозиторій не повертає успіх. Для майбутніх інтеграцій замініть відповідний адаптер у `AppContainer`; тестові реалізації передаються через його конструктор. Не підставляйте «успіх» у продукційний непідключений адаптер.

### Виправлені сценарії

Повернення із завдань більше не зациклюється; деталі стоянки, параметри маршруту й корпоративні налаштування повертають до фактичного викликача. Підсумок відкриває історію; активна навігація — пошук зупинок. Ford переходить до особистого профілю параметрів, а не MAN. Деталі завдання передають його ідентифікатор і адресу до плану / планування маршруту. Застосування параметрів оновлює спільний стан. Приватна поїздка не стає робочою від відкриття завдання; для роботи потрібні членство та явний контекст. Згода на видалення акаунта початково **вимкнена**.

## Запуск

Android-збірка:

```sh
./gradlew :androidApp:assembleDebug
```

Для запуску Android використовуйте конфігурацію в Android Studio. Для iOS відкрийте `iosApp/iosApp.xcodeproj` у Xcode та запустіть схему `iosApp` на симуляторі або пристрої; потрібні macOS і Xcode.

## Тести

```sh
./gradlew :shared:testAndroidHostTest
./gradlew :shared:iosSimulatorArm64Test
```

Тести покривають валідацію авторизації / транспорту, контракти непідключених адаптерів, згоду й повторні запити, навігаційні повернення, фільтрацію прикладів та спільний стан. Вони не є UI-тестами всіх екранів і не перевіряють реальні GPS, XR чи сервери.

Перевірка iOS-збірки без підпису:

```sh
xcodebuild -project iosApp/iosApp.xcodeproj -scheme iosApp -configuration Debug \
  -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build/ios-validation CODE_SIGNING_ALLOWED=NO build
```
