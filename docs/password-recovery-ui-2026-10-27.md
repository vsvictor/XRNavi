# XRNavi — локальне відновлення пароля S41–S45

Дата: 2026-10-27. Пакет: `recovery-ui-2026-10-27-8743f0a2`.

**S41 реалізовано у звичайній навігації; S42–S45 — лише внутрішній
debug/preview. Серверної реєстрації, листів, перевірки токенів, зміни пароля
та створення сесії немає. P0–P4 залишаються «Відкладено».**

Попередній звіт S02:
[Registration UI Verification](https://github.com/vsvictor/XRNavi/wiki/Registration-UI-Verification-2026-10-27).
Його історію та докази не переписано. За окремим дозволом користувача
[звіт опубліковано на wiki](https://github.com/vsvictor/XRNavi/wiki/Password-Recovery-UI-Verification-2026-10-27),
wiki-коміт `a0d6307`. Опубліковано 18 screenshots, 4 JSON-документи й manifest
публікації. Сторінка та всі 24 raw URL (звіт і 23 файли доказів) доступні
через HTTP 200; байти raw-файлів звірено за SHA-256.
Код застосунку не комічено й не пушено; provisioning не виконувався.

## Реалізація та межі

| Стан | Доступ і поведінка |
|---|---|
| S41 — відновлення | SignIn → «Забули пароль?». Пошта з базовою локальною перевіркою, помилки після редагування/втрати фокусу, активна дія лише для коректного формату. Submit лишає S41 і показує «Відновлення пароля ще не підключено. Дані не надіслано». |
| S42 — перевірте пошту | Лише явний вибір у debug-меню. Текст не стверджує надсилання листа. Повторний запит показує непідключений сервіс; «Відкрити пошту» також чесно повідомляє про відсутню інтеграцію. «Змінити адресу» повертає S41. |
| S43 — новий пароль | Лише preview, не приймає reset-token. Два поля, незалежна видимість, мінімум 8 символів, точне підтвердження без trim/нормалізації; «Паролі не збігаються». Submit очищує секрети, повідомляє, що пароль не змінено, і **не** переходить у S44. |
| S44 — пароль змінено | Лише ілюстративний стан із заголовком «· демо» та явним поясненням, що пароль насправді не змінено, акаунт і сесію не створено. Повернення до SignIn, без auto-login. |
| S45 — посилання недійсне | Лише ілюстрація, без отримання або перевірки справжнього токена. Новий запит повертає S41, не імітує надсилання листа. |

У звичайної форми немає автоматичного переходу до демонстраційних станів.
У debuggable Android-збірці внизу recovery є «Внутрішній preview S41–S45 · debug»;
меню дозволяє явно вибрати стан. На iOS доступ визначається
`Platform.isDebugBinary`. У production/non-debug режимі entry не відображається;
ViewModel також відхиляє відкриття preview. Release runtime окремо не запускався.

Використано поточні тему, Orbit/XRNavi/Mobile space, ViewModel та ресурси.
Валідацію пошти/паролів, поле з повідомленнями помилок/видимістю та BackHandler
спільно використовують S02 і recovery; паралельної реєстрації не створено.
Контракт S02, його повідомлення submit та очищення секретів збережено.

Паролі й підтвердження є лише станом ViewModel в оперативній пам'яті:
без `rememberSaveable`, SavedState, налаштувань або діагностичного виведення.
Вихід, перемикання preview, локальне завершення та `onCleared` очищують поля
й видимість. Це очищення стану, а не обіцянка криптографічного занулення
immutable-рядків у пам'яті. Після перезапуску процесу секрети не відновлюються.

Одна адаптивна реалізація вибирає компонування за доступною шириною/висотою:
дві колонки за достатньої ширини в Landscape; вузьке вікно — одна колонка;
tablet-розмір визначається коротшою стороною, не самою орієнтацією.
Є системні відступи, IME-відступи, прокручування, Next/Done, компактний header
і приховування декоративного фото за малої висоти. Semantics полів, помилок,
видимості й заголовків додано, але це **не** перевірка читачів екрана.

Map, адресний контракт, транспорт, Preview та Splash у цьому пакеті не змінено.
Associated Domains, entitlements, signing, production deep links і нові SDK
не додавалися.

## A — незалежно виконано в цьому циклі

### Збірки й тести

Виконано послідовно з IDE-збіркою, без одночасного IDE/CLI build:

```text
./gradlew :androidApp:assembleDebug :shared:testAndroidHostTest :shared:compileKotlinIosSimulatorArm64 --console=plain
```

Фінальний результат — `BUILD SUCCESSFUL`. Android Debug APK зібрано та
встановлено. Спільну iOS Simulator Arm64-бібліотеку скомпільовано;
це **не** iOS UI-запуск. Є попередження про deprecated iOS BackHandler;
signing, Account або profiles для цієї компіляції не змінювалися.
Перший iOS compile вимагав opt-in для `ExperimentalNativeApi`; його додано,
після чого фінальний compile успішний.

Навмисні відмінності: тексти про непідключений сервіс і demo замість

## C — історичні результати

Результати S02 і Map/launch з попередніх звітів залишаються історичними.
Відома відмінність **cockpit-банера S02** цим recovery-пакетом не закрита:
збіг recovery-ресурсів Mustang не є доказом виправлення S02.
Не повторювалися історична iOS launch-діагностика, provisioning або фізичний X9.

## D — не перевірено / відкладено

- iOS recovery runtime на Simulator/фізичному пристрої; була лише спільна компіляція.
- Окремий фізичний телефон, повна матриця всіх S41–S45 × 8 форматів/тем,
  Release runtime; наявні докази не підміняють ці конфігурації.
- VoiceOver/TalkBack та реальні оголошення: не запускалися.
- P0–P4 попереднього циклу — **«Відкладено»**, включно з організаційно
  відкладеним TalkBack і Dark/max. Доступ до правильної X9 Team тут не підтверджувався.
- iOS runtime S02 і його cockpit-відмінність залишаються відкритими.
- Серверні auth/reset/mail/token/rate-limit, native mail integration і юридична
  готовність не реалізовані й не перевірені. Довільний рядок не приймається за token.
