# S02 — локальний UI реєстрації XRNavi

Дата: 27.10.2026. Окремий пакет; **P0–P4 залишаються «Відкладено»**.
Commit, push і публікація не виконувалися.

## Реалізація

Попередньої форми реєстрації не було. У наявну навігацію додано перехід
SignIn → реєстрація → SignIn; Map, адресний контракт, транспорт, Preview,
Splash і signing settings у цьому пакеті не змінювалися.

`RegistrationViewModel` використовує наявний підхід Compose state /
ViewModel factory. Є ім’я, пошта, пароль і підтвердження, незалежна
видимість обох паролів, згода, «Особистий / Корпоративний», доступна лише
за валідного стану дія й повернення через header, нижнє посилання або Back.
Початкових помилок немає; після редагування/втрати фокусу показано локальні
помилки. Підтвердження порівнюється точно: «Паролі не збігаються».
Політика пароля — лише мінімум 8 символів, без trim/нормалізації чи
додаткових вимог до складу.

Submit не змінює екран на Map, не створює акаунта/сесії й не робить запиту:
**«Реєстрацію ще не підключено. Дані не надіслано»**.
Обидва паролі й видимість очищуються після обробки валідної форми,
скасування та завершення ViewModel. Секретний стан не використовує
rememberSaveable, SavedState, налаштування або діагностичний запис.
Нове створення ViewModel не відновлює паролів.

Корпоративний режим прямо пояснює необхідність запрошення та
непідключений сценарій. Документи позначені недоступними; діалог пояснює,
що юридичну частину не завершено. Вигаданих URLs, листів, OAuth, серверної
перевірки, сесій, таймерів чи фіктивних мережевих запитів немає.

Компонування визначається доступними розмірами вікна, не Figma px.
Підтримано один стовпець або дві області, обмеження ширини форми,
safe drawing insets на рівні App, IME-відступи, прокручування,
явний Next між чотирма полями та Done для закриття клавіатури.
У низькому Landscape з клавіатурою заголовок компактний, декоративний
банер прибирається. Є назви полів, помилки, selected/checked/disabled
і стани видимості паролів. Це не є перевіркою читачів екрана.

## Дизайн і відома відмінність

Через підключений Figma MCP прочитано screenshots усіх восьми S02 nodes
файлу `atSi2dQTrI7763POEO2w1a`: Dark `3:11518`, `111:43`, `95:75088`,
`81:60541`; Light `179:363`, `179:4006`, `179:5977`, `179:9537`.
Отримано також metadata телефонного Portrait.

Структурний `get_design_context` для трьох екранів і окремого банера
завершився timeout. Тому **повну візуальну відповідність Figma не
заявлено**: замість cockpit-зображення S02 використано наявні
`mustang_hero_light/dark`, як у вже реалізованому SignIn.
Збережено поточну тему, шрифти, Mobile space / XRNavi та затверджений Orbit.
Додаткові пояснення про непідключені документи/запрошення збільшують
висоту форми порівняно з презентаційним макетом; дії доступні через scroll.

## A — незалежно виконано в пакеті

| Перевірка | Умови й результат |
|---|---|
| Android Debug | `:androidApp:assembleDebug` — успіх |
| Локальні тести | `:shared:testAndroidHostTest` — 22/22, без failures/errors/skipped: 10 нових RegistrationViewModel, 12 наявних |
| iOS спільна компіляція | `:shared:compileKotlinIosSimulatorArm64` — успіх, без Xcode provisioning; є попередження deprecated BackHandler API |
| Фізичний Android S02 | Samsung SM-X135F, Android 16/API36, build `X135FXXS5BZI3`, density 213, font scale 1.0; TalkBack вимкнений |
| Планшетне вікно | 800×1340 та 1340×800 physical px, Light/Dark, Portrait/Landscape; панель Map — N/A |
| Телефонне тестове вікно | На тому самому Samsung тимчасове `wm size 480x1040`, Portrait/Landscape, Light/Dark; це не окремий фізичний телефон |

Нові тести покривають порожню форму без передчасних помилок, ім’я/пошту,
7/8 символів і відсутність додаткових обмежень пароля, точний збіг,
згоду в обох режимах, незалежну видимість, невалідний submit, чесне
повідомлення валідного submit, очищення при скасуванні й `ViewModelStore.clear()`.

Touch-прохід на Android підтвердив: відкриття S02, відкладені помилки,
некоректну пошту, mismatch і виправлення, незалежність першого перемикача,
валідність і паролі лише в пам’яті після теми/повороту, submit без переходу
на Map, пояснення документів/запрошення та повернення у SignIn.
Окремо перевірено довгі ім’я/пошту, клавіатуру, Next, прокручування до CTA
й нижнього повернення, очищення скасованого сценарію та Android Back
у телефонному тестовому вікні. У звітах і screenshots немає відкритих паролів.

Після проходів розмір екрана повернуто до physical 800×1340, rotation 0,
автоповорот увімкнено, TalkBack залишається вимкненим. TTS/locale та
налаштування iPad не змінювалися.

## B / C / D та межі підтвердження

**B:** нових результатів проходження від користувача немає.

**C:** історичні Map/Splash результати залишаються у попередньому звіті;
вони не є новим runtime-проходом у цьому пакеті. Наявні common-регресії
успішні, але повний повторний Map/Splash UI-прохід не заявляється.

**D:** фактичний запуск S02 на iOS, фізичний телефон, реальні
VoiceOver/TalkBack, абсолютна візуальна відповідність cockpit-банеру Figma,
серверна/корпоративна реєстрація та юридичні документи не підтверджені
або не підключені. Перевірки P0–P4, provisioning, фізичні X9 UI-тести
і відкладене Dark/max доопрацювання не запускалися.
Це не готовність релізу або серверної авторизації.
